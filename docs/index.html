Why these two techniques

The CV is terse and keyword-style; questions are conversational.

Pre-retrieval: Multi-Query

  • The LLM rewrites the question in CV vocabulary, e.g. "expected graduation year, GPA".
  • Broad questions fan out across several chunks.
  • Not HyDE: a fake CV passage could inject invented details.
  • Self-Query and routing do not apply: the only metadata is the page number.
  • The original question is always kept, and the app falls back to it if the LLM call fails.

Post-retrieval: cross-encoder rerank

  • Multi-Query raises recall but adds noise; the reranker restores precision.
  • It reads question and chunk together, which judges relevance better than comparing two separate embeddings.
  • Local and free, unlike a hosted reranker such as Cohere.
  • Not contextual compression: that costs one LLM call per chunk and can drop numbers a CV depends on.
  • It scores against the original question, so rewrites cannot drift the result.

FAQ


Model not found (404)
Hosted model names get retired. Check console.groq.com/docs/models and update the model name in src/rag.py. It is used for answering and for Multi-Query.


"[multi-query] LLM call failed" in the terminal
Usually a rate limit or a retired model. The app keeps working with the original question only, and reranking still applies.


Empty or irrelevant answers
Run python -m src.ingest again and confirm it reports more than 0 chunks (12 for the included CV).


How do I compare naive and improved retrieval?
Run python -m src.compare. It prints both top-4 lists side by side for several questions.


Can I use my own CV?
Replace data/cv.pdf and run python -m src.ingest again.
